# Teacher guide

## What LogicLearn is

- A browser-based logic-circuit editor with two units of short lessons: gates and truth tables (Unit 1), then building with gates (Unit 2). Each unit ends with an open project.
- No accounts and no data collection: progress is saved in each student's browser. Students can save it to a file and load it on another computer (Lessons page).
- Works on Chromebooks, iPads and laptops, with a mouse, a touch screen or the keyboard alone, and with screen readers. See **⚙ Accessibility** for high contrast, dark mode, a dyslexia-friendly font and read-aloud.

## Getting started

- Students open the site and start **Lesson 1** (the **editor tour** is optional, for anyone new to the editor).
- Lessons open in order. A student who already knows a unit can take its **test-out** (three challenges, no hints) to skip ahead.
- To let one student skip ahead without the test-out, give them the lesson's **unlock code** (teacher view → Unlock codes). They type it on the locked lesson.

## Pacing

| Period             | Suggested pace                                                  |
| ------------------ | --------------------------------------------------------------- |
| 45 minutes         | One lesson per period; the unit project over two periods.       |
| 50 minutes         | One lesson per period, with time to discuss the challenge.      |
| 90 minutes (block) | Two lessons per block, or one lesson and half the unit project. |

- Lesson 6 (XNOR and "if … then") is the hardest: allow extra time.
- Each lesson ends with a challenge where outputs stay hidden until **Check**: a good moment to ask students to explain their reasoning.

## Help built into the lessons

- Hints go from general to specific: the gate or idea, then "look at your circuit", then one row worked through. None gives the whole answer.
- A failed check shows one row where the circuit is wrong, and can set the switches to it.
- Recognized mistakes (for example OR built where XOR was wanted) get a targeted message, and can offer a short **practice** step and a **walkthrough** of the idea.

## Projects and rubrics

- **Unit 1 project:** a door alarm or a voting machine. Students fill in the open rows of the rule, then build it; the checklist checks the rule and the circuit.
- **Unit 2 project:** a number display (0–3 on a seven-segment display).
- Hidden rubric (for your grading, beyond the automatic checklist):
  - explains the design choices in the rule (why panic works when the alarm is off, or what "passes" means);
  - clear labels and a tidy layout;
  - tested every row before checking.

## Checking progress

- Students print **My progress report** (Lessons page). It ends with a **completion code**.
- In the teacher view, **Check a completion code** shows which lessons, projects and test-outs the code says are finished, and the date it was made. A changed or mistyped code doesn't check out.
- Codes discourage rather than secure: LogicLearn's source is public, so a determined student could work a code out. Use them alongside what you see in class.

## The answer key

- Teacher view → **Answer key**: for every step, the table to build and a working circuit (in words, with a link that opens a copy in the sandbox). Project examples are there too.
- Keep the teacher code to yourself: the answer key is behind it.
